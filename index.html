Amazon Athena
SQL serverless sobre S3
Concepto
Servicio de consultas interactivas serverless que permite analizar datos directamente en Amazon S3 usando SQL estándar (compatible con ANSI SQL). No requiere infraestructura, no hay servidores que gestionar.
Características clave
Serverless Pay-per-query S3 nativo Presto/Trino
Formatos soportados
CSV, JSON, ORC, Avro, Parquet. Soporta datos comprimidos. Integración con AWS Glue Data Catalog.
Casos de uso
  • Análisis de logs de CloudTrail, ELB, CloudFront
  • Consultas ad-hoc sobre data lakes en S3
  • Informes de negocios sin ETL previo
  • Análisis de click-stream de usuarios
🧸 Para Dummies
Imagina que tienes miles de archivos CSV guardados en un disco duro (S3). Athena te deja hacer preguntas en SQL ("¿cuántas ventas tuve en enero?") sin mover esos archivos ni montar servidores. AWS busca en todos los archivos automáticamente y te da la respuesta. ¡Solo pagas por los datos que revisó!
💳 Cómo te cobra
Por datos escaneados: $5.00 por TB escaneado en S3.
Tip de ahorro: Usar Parquet u ORC puede reducir el escaneo hasta 90% → mismo resultado, 90% menos costo.
DDL y metadatos: Crear/borrar tablas es ✓ GRATIS
Consultas canceladas: Si cancelas antes de terminar, pagas por lo ya escaneado.
Federated queries: $1.00/TB adicional si consultas fuentes externas (RDS, DynamoDB, etc.).
💡 Tip de Examen
Athena = SQL + S3 sin servidores. Cobro por TB escaneado. Parquet/ORC reduce costos hasta 90%. Integra con Glue Data Catalog para esquemas.
📝 Pregunta de Examen
Una empresa almacena logs de acceso en formato JSON en S3 y necesita ejecutar consultas SQL ocasionales sin aprovisionar infraestructura. ¿Qué servicio es más adecuado?
Respuesta: Amazon Athena — permite consultar directamente los datos en S3 con SQL estándar, sin servidores, pagando solo por TB escaneado.

Amazon EMR
Elastic MapReduce — Big Data en clúster
Concepto
Plataforma administrada de clúster para procesamiento de Big Data. Ejecuta frameworks distribuidos como Apache Hadoop, Spark, Hive, HBase, Flink, Presto sobre EC2, EKS o de forma serverless.
Frameworks disponibles
Apache Spark Hadoop Hive Presto HBase
Casos de uso
  • ETL masivo (transformación de terabytes)
  • Machine Learning a escala
  • Procesamiento de logs y clickstreams
  • Análisis genómico y científico
  • Indexación de búsqueda web
🧸 Para Dummies
¿Necesitas procesar 10 millones de registros pero tu laptop tardaría una semana? EMR es como contratar 500 empleados temporales (servidores), repartirles el trabajo, que cada uno haga su parte y luego te entreguen el resumen. Cuando terminan, los "despides" y dejas de pagar. Tú solo dices qué hacer (Spark, Hadoop), ellos hacen la magia.
💳 Cómo te cobra
EC2 + recargo EMR: Pagas la instancia EC2 más un recargo. Ej: m5.xlarge = $0.048/h EC2 + $0.048/h EMR = ~$0.096/h total.
EMR Serverless: $0.052/vCPU-hora + $0.0057/GB-memoria-hora. Solo pagas lo que consumes.
Spot Instances: Reducen costo hasta 70% en nodos Task (los que pueden interrumpirse).
El servicio EMR en sí: No tiene costo fijo — el cargo se suma a la infraestructura subyacente.
💡 Tip de Examen
EMR = Big Data con Spark/Hadoop administrado. EMR Serverless elimina gestión de clústeres. Spot en nodos Task para máximo ahorro. Para procesar terabytes sin gestionar infraestructura manual.
📝 Pregunta de Examen
Una empresa necesita procesar terabytes de datos usando Apache Spark y Hadoop con control sobre la configuración del clúster. ¿Qué servicio deben usar?
Respuesta: Amazon EMR — plataforma de clúster administrado para Big Data que ejecuta Spark, Hadoop, Hive y otros frameworks con control granular.

AWS Glue
ETL serverless y catálogo de datos
Concepto
Servicio de integración de datos serverless. Descubre, prepara y combina datos para análisis, ML e ingeniería de datos. Incluye el Glue Data Catalog (repositorio central de metadata).
Componentes
Data Catalog ETL Jobs Crawlers DataBrew
Casos de uso
  • Catálogo centralizado de datos para Athena/Redshift
  • Transformación y limpieza de datos (ETL)
  • Preparación de datos para ML
  • Descubrimiento automático de esquemas (Crawlers)
🧸 Para Dummies
Glue es tu asistente de limpieza de datos. Imagina que recibes archivos de ventas en formatos distintos (CSV, JSON, Excel) de 5 sucursales diferentes. Glue: 1) va y revisa todos esos archivos (Crawler), 2) convierte todo al mismo formato limpio (ETL Job), y 3) guarda un catálogo de qué datos tienes y dónde están (Data Catalog) para que Athena o Redshift puedan encontrarlos fácil.
💳 Cómo te cobra
ETL Jobs: $0.44 por DPU-hora (1 DPU = 4 vCPUs + 16 GB RAM). Mínimo 1 minuto de cobro.
Crawlers: $0.44 por DPU-hora. Mínimo 10 minutos de cobro por ejecución.
Data Catalog: ✓ 1M objetos GRATIS luego $1 por 100K objetos/mes.
DataBrew: $1.00/nodo interactivo/hora; $0.48/nodo en jobs batch.
Glue Studio: Sin costo adicional por la interfaz visual.
💡 Tip de Examen
Glue = ETL serverless. Glue Data Catalog es el "directorio" central que usan Athena, EMR y Redshift Spectrum. Crawlers descubren esquemas automáticamente. DataBrew para transformaciones sin código.
📝 Pregunta de Examen
Una empresa tiene datos en distintos formatos en S3 y necesita descubrir automáticamente su esquema y catalogarlos para que Athena pueda consultarlos. ¿Qué servicio resuelve esto?
Respuesta: AWS Glue — sus Crawlers descubren esquemas automáticamente y los registran en el Glue Data Catalog, que Athena usa para conocer la estructura de los datos.

Concepto
Data warehouse en la nube totalmente administrado y a escala de petabytes. Basado en PostgreSQL, usa almacenamiento columnar y procesamiento masivo paralelo (MPP) para consultas analíticas muy rápidas.

MPP Columnar Serverless option ML integrado
Casos de uso
  • Data warehousing empresarial
  • OLAP (procesamiento analítico en línea)
  • Consolidación de datos de múltiples fuentes
  • Reportes históricos a gran escala
🧸 Para Dummies
Si RDS es tu cajón de escritorio (rápido para guardar y sacar cosas una a una), Redshift es un almacén industrial gigante optimizado para análisis. Pregunta "¿cuánto vendimos en total por región en los últimos 5 años?" y te responde en segundos aunque tenga petabytes de datos. No sirve para ventas en tiempo real (para eso usa RDS/DynamoDB), sirve para análisis históricos masivos.

✓ Free Tier 2 meses de nodo dc2.large (160 GB SSD, 2 vCPUs) en el primer año.
💡 Tip de Examen
Redshift = data warehouse OLAP (no OLTP). RA3 separa cómputo de almacenamiento. Serverless para cargas variables. Spectrum para consultar S3 sin cargar datos. Almacenamiento columnar = consultas analíticas ultrarrápidas.

Concepto

💡 Tip de Examen
EventBridge = enrutador de eventos serverless. Antes: CloudWatch Events. Eventos de AWS al bus Default son GRATIS. Scheduler reemplaza cron jobs. Para integración con SaaS usa Partner Event Sources.

Amazon SNS
Simple Notification Service — Pub/Sub
Concepto
Servicio de mensajería pub/sub totalmente administrado. Envía notificaciones desde publicadores a múltiples suscriptores (fanout). Soporta push a móviles, SMS, email, Lambda, SQS, HTTPS.
Protocolos soportados
HTTP/HTTPS Email SMS Lambda SQS
Casos de uso
  • Alertas de monitoreo a múltiples canales
  • Notificaciones push en apps móviles
  • Patrón fanout (SNS → múltiples SQS)
  • Notificaciones de eventos de negocio
🧸 Para Dummies
SNS es como un megáfono: una persona habla (el publicador) y todos en el estadio escuchan al mismo tiempo (los suscriptores). Si publicas "ocurrió un error crítico", simultáneamente: llega un email al admin, un SMS al ingeniero de guardia, y un mensaje a Lambda para que intente arreglarlo solo. Un mensaje → muchos destinos, al mismo tiempo, sin que el emisor sepa quiénes están escuchando.
💳 Cómo te cobra
Publicaciones al topic: $0.50 por millón de requests API.
Entregas HTTP/HTTPS: $0.60 por millón.
Entregas Lambda/SQS/Firehose: $0.50 por millón.
Email: $2.00 por 100,000 mensajes.
SMS (México): ~$0.071 por mensaje. USA: ~$0.006.
Push móvil: $1.00 por millón de notificaciones push.
✓ Free Tier 1M publicaciones + 100K entregas HTTP + 1,000 emails + 100 SMS gratis/mes.
💡 Tip de Examen
SNS = pub/sub, 1 a muchos (push). SQS = cola, 1 a 1 (pull). SNS FIFO solo acepta SQS FIFO como suscriptor. Patrón Fanout: 1 SNS topic → múltiples SQS queues para procesamiento paralelo.
📝 Pregunta de Examen
Una empresa necesita notificar simultáneamente por email, SMS y Lambda cuando ocurre un error crítico en su sistema. ¿Qué servicio cumple este requerimiento?
Respuesta: Amazon SNS — modelo pub/sub que envía un mensaje a múltiples suscriptores (email, SMS, Lambda, SQS) simultáneamente (fanout).

Amazon SQS
Simple Queue Service — Cola de mensajes
Concepto
Servicio de colas de mensajes totalmente administrado. Desacopla y escala microservicios, sistemas distribuidos y aplicaciones serverless. Garantiza entrega al menos una vez.
Tipos de colas
Standard
Alta thr., orden best-effort
FIFO
Orden exacto, exactly-once
Casos de uso
  • Desacoplar frontend de backend
  • Buffer ante picos de tráfico
  • Procesamiento asíncrono de tareas
  • Dead letter queue para mensajes fallidos
🧸 Para Dummies
SQS es como un buzón entre dos personas que trabajan a distintos ritmos. El que produce mensajes los deja en la cola y sigue con su vida (no espera al otro). El consumidor los recoge cuando puede. Si el consumidor se cae, los mensajes esperan hasta 14 días. Esto evita que si tu backend se satura de golpe, no pierdas pedidos — simplemente se van acumulando en la cola para procesarse después.
💳 Cómo te cobra
Por solicitudes API: $0.40/millón de requests (Standard). $0.50/millón (FIFO).
Ojo: Cada 64 KB cuenta como 1 request. Un mensaje de 256 KB = 4 requests facturadas.
Data transfer: Entre SQS y EC2/Lambda en la misma región: ✓ GRATIS
✓ Free Tier PERMANENTE 1 millón de requests/mes gratis para siempre (no solo 12 meses).
💡 Tip de Examen
SQS desacopla productor de consumidor. Standard = alto throughput, orden best-effort. FIFO = orden exacto, exactly-once (para pagos, inventario). Dead Letter Queue para mensajes que fallan repetidamente. Long Polling reduce costos.
📝 Pregunta de Examen
Una aplicación recibe picos de tráfico que su backend no puede procesar inmediatamente, causando pérdida de solicitudes. ¿Qué servicio ayuda a desacoplar y absorber estos picos?
Respuesta: Amazon SQS — cola de mensajes que actúa como buffer entre productor y consumidor, evitando pérdida de solicitudes durante picos de tráfico.
🔑 Palabras Clave
desacoplarcola de mensajesbufferprocesamiento asíncronopullFIFO

Step Functions = orquestador visual de servicios AWS. Standard (hasta 1 año, exactamente-una-vez) para procesos de negocio. Express (hasta 5 min, alta frecuencia) para IoT/streaming. Maneja reintentos, errores y paralelismo.

🏗️ AWS Well-Architected Framework
AWS WAF

Marco con mejores prácticas para diseñar y operar sistemas cloud seguros, eficientes, resilientes y económicos. Se basa en 6 pilares fundamentales que guían cada decisión arquitectónica desde el diseño inicial hasta la operación continua.

Definición oficial
El AWS Well-Architected Framework proporciona un conjunto consistente de preguntas que permiten evaluar arquitecturas cloud e identificar el impacto de las decisiones técnicas. Construido sobre 6 Pilares con cientos de mejores prácticas, permite identificar riesgos y oportunidades de mejora en cualquier workload. La herramienta gratuita Well-Architected Tool aplica estos pilares mediante cuestionarios guiados.

Definición
Capacidad de ejecutar y monitorear sistemas para entregar valor de negocio y mejorar continuamente procesos y procedimientos de soporte. Incluye operaciones como código, cambios frecuentes y pequeños, anticiparse a fallos y aprender continuamente.
Explicación
¿Cómo de bien corres y mejoras tu operación día a día? Es como un equipo de F1 que optimiza cada pitstop, no espera a que el coche se rompa. Automatizar tareas manuales, aprender de cada fallo y mejorar constantemente los procesos. Todo lo operacional debe poder ejecutarse como código, no con clics manuales.

💡 Tip de Examen
Excelencia Operacional = automatización y mejora continua. Servicios: CloudFormation, CodePipeline, CloudWatch, Systems Manager. Si menciona "runbooks", "IaC", "operaciones automatizadas", "aprender de incidentes" → este pilar.

Explicación
¿Está tu arquitectura protegida en cada capa? Como el sistema de seguridad de un banco: múltiples puertas con cerraduras diferentes, cámaras grabando todo, y un plan de respuesta si entran. Nunca confíes en nadie por defecto (zero trust): verifica todo, encripta todo, registra todo.

least privilegedefensa en profundidadencriptacióntrazabilidadzero trust

Una fintech implementa IAM con MFA obligatorio, KMS para encriptar RDS y S3, GuardDuty para detección continua y CloudTrail con 1 año de retención para auditoría.
03
Confiabilidad
Reliability
Definición
Capacidad de un workload de realizar su función prevista correctamente y de forma consistente. Incluye recuperación automática de fallos, escalado horizontal, pruebas de recuperación y gestión de cambios.
Explicación
¿Tu sistema sigue funcionando cuando algo falla? Como un avión con múltiples motores: si uno falla, los demás mantienen el vuelo. Diseña asumiendo que TODO fallará eventualmente — servidores, redes, zonas enteras. Tu arquitectura debe sobrevivir y auto-recuperarse sin intervención humana.
Principios de diseño
Recuperarse automáticamente · Probar recuperación · Escalar horizontalmente · Dejar de adivinar capacidad · Gestionar cambios con automatización
💡 Tip de Examen
Confiabilidad = disponibilidad y recuperación de fallos. Servicios: Multi-AZ, Auto Scaling, Route 53 Failover, S3, DynamoDB. Si menciona "alta disponibilidad", "DR", "fault tolerance", "RPO/RTO" → este pilar.

alta disponibilidadMulti-AZRPO / RTOfault toleranceauto-recuperación

Una empresa quiere que su app siga disponible aunque falle una zona de disponibilidad completa. ¿Qué pilar del WAF guía este diseño?
Respuesta: Confiabilidad — diseñar para fallos con Multi-AZ, Auto Scaling y recuperación automática para mantener la disponibilidad.
🌍 Ejemplo Real

Explicación
¿Estás usando el servicio y tamaño correcto para cada trabajo? Es como elegir el vehículo adecuado: no mandas un camión a comprar el pan. Elegir el tipo de instancia EC2, motor de BD o arquitectura (serverless, contenedores) exacto para cada necesidad maximiza el rendimiento sin pagar de más.

Optimización de Costos
Cost Optimization
Definición
Capacidad de ejecutar sistemas para entregar valor de negocio al precio más bajo posible. Incluye gestión de gasto, selección del modelo de precio correcto, medición del ROI y eliminación de recursos ociosos.
Explicación
¿Estás pagando solo por lo que realmente necesitas? En la nube es muy fácil gastar dinero sin darse cuenta. Este pilar enseña a apagar lo que no se usa, elegir Reserved Instances para cargas predecibles, Spot para trabajos tolerantes, y medir cada dólar gastado con etiquetas (tags) por departamento o proyecto.
Principios de diseño
Implementar gestión financiera cloud (FinOps) · Modelo de consumo · Medir eficiencia · Dejar de gastar en trabajo indiferenciado · Analizar y atribuir gastos

Sostenibilidad
Sustainability (2021)
Definición
Minimizar los impactos ambientales de ejecutar cargas de trabajo en la nube. Cubre comprensión del impacto ambiental, metas de sostenibilidad, maximizar utilización y adoptar hardware y software más eficiente.
Explicación
El pilar más nuevo (añadido en 2021). En la nube, menos recursos usados = menos energía consumida = menor huella de carbono. AWS ya es 3.6x más eficiente energéticamente que datacenters on-premises. Este pilar te guía a ser aún más eficiente: usar procesadores Graviton (ARM), preferir serverless y apagar lo ocioso.
Principios de diseño
Entender tu impacto · Metas de sostenibilidad · Maximizar utilización · Adoptar hardware eficiente (Graviton) · Usar servicios administrados · Reducir impacto downstream
💡 Tip de Examen
Sostenibilidad = el pilar más nuevo (2021). Si menciona "huella de carbono", "eficiencia energética", "impacto ambiental", "Graviton", "reducir recursos" → este pilar. Beneficio adicional: menos uso = menos costo.
